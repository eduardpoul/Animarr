## 1. Главное

1. **Смена качества может уничтожить плеер.** Если `/api/hls/start` падает, остаётся чёрный экран без панели управления. Оверлей переживает даже переход на другую страницу, спасает только перезагрузка **[live]**.
   - На Windows так падает любой fMP4-план: ffmpeg кладёт `init.mp4` в рабочую папку сервера.
   - На проде (Linux) этой причины быть не должно, но механизма восстановления после ошибки старта нет нигде.
2. **На ТВ субтитры не рисуются вообще.** Нет ни `SubtitleView`, ни `onCues`. Пункт в меню выбирается, а на экране пусто **[код]**.
3. **Русские SRT в cp1251 не работают:** `/api/subtitle` отдаёт 422, субтитры молча пустые **[live]**.
4. **Любой перезапуск потока что-то теряет.** Смена дорожки, качества или автопереключение языка сбрасывают:
   - метаданные сессии: заголовок становится именем файла **[live]**, пропадают skip intro / up next / автопереход, превью перемотки и lock screen;
   - выбранные субтитры, соотношение сторон, паузу и mute **[live]**.
5. **Стили ASS теряются.** Сервер превращает ASS в WebVTT: позиции, цвета, надписи и шрифты пропадают **[live]**. Для аниме это критично.
6. **Аудиодорожки на ТВ.** В Direct Stream и HLS доступна только первая дорожка. Внешние озвучки и субтитры на ТВ недоступны совсем **[код]**.
7. **Две одновременные сессии на одном файле ломают друг друга.** Дедупликация по пути обрывает сессии других пользователей и устройств (TV + веб, два профиля) **[код]**.
8. **Сервер транскодирует то, что клиенты умеют сами.** AV1, VP9 и Hi10P в браузерах на ПК, 5.1-звук, MKV на ТВ. Отчёт ТВ о кодеках врёт: `mpeg4`, `av1`, `m2ts` (раздел 5).
9. **HDR и Dolby Vision при перекодировании становятся «плоским» SDR без tone mapping.** DV P5 на устройствах без DV показывается с неверными цветами.
10. **Нет базовых функций плеера:** скорость, глав, сдвиг субтитров, стиль субтитров, режимы Fit/Fill/Stretch/Zoom, память выбора по сериалу.

### Низкая серьёзность (вкратце)

- Пресеты aspect кадрируют.
- На ТВ нет 21:9 / 2.35 / 1.85.
- Поворот на ТВ игнорируется.
- «Default» перебивается автокропом.
- HUD не локализован.
- DLNA: нет субтитров, игнорируется `StartTimeMs`, не выбрать дорожку.
- `/api/playlist.m3u` жёстко задаёт `http:8080`.
- `maxHeight` не валидируется: нечётное значение роняет libx264.
- CODECS захардкожены; MP2 объявляется как `mp4a.40.2`.
- `SubtitleSize`: ограничение 10–48 против документированных 12–32.
- На ТВ ⏭ игнорирует сохранённую позицию.
- На ТВ в `ⓘ` битность определяется эвристикой.
- Мёртвый код:
  - веб: NativeAdapter, `OnPlayerMediaInfo`, `GetMpvDeepLink`;
  - ТВ: `NativePlayerBridge`, `SetSubtitleAsync`, TextureView.
- Устаревшие комментарии: ffmpeg 5.1, «AC3 в Chrome», libass-wasm, «3 плана».

## 5. Кодеки и форматы

### 5.1 Сколько лишнего транскода сейчас

- **Веб.** Сообщает только `clientHevc`/`clientHevc10` (JS:2282-2307), `MediaCapabilities` не используется. Поэтому AV1, VP9, VP8, WebM и Hi10P **всегда** перекодируются (HSS:381, 425).
- **Телефон.** Нативный плеер отключён (NPS:266-282), работает WebView. В нём нет AC-3, E-AC-3, DTS, TrueHD и DV; HDR не гарантирован; субтитры только WebVTT.
- **ТВ.** Отчёт о кодеках врёт (B28). DV никогда не играется нативно (HSS:341), даже P8, который Media3 сама проиграла бы как HDR10.
- **Звук.** Почти везде AAC 2.0.
- **Чего нет на сервере:** tone mapping, деинтерлейс, вжигание субтитров, путь «перекодировать только звук».

### 5.3 Неизбежный транскод

- **Старые кодеки** — MPEG-2, MPEG-4 ASP, VC-1/WMV, MPEG-1, RealVideo, Theora. Для браузеров и телефонов всегда; на ТВ — если у SoC нет декодера. Обычно это SD, VAAPI справляется дёшево.
- **H.264 Hi10P** — везде, кроме десктопных Chrome/Edge и ТВ на Rockchip. Цель — HEVC Main10.
- **DV P5** — на клиентах без DV.
- **Звук DTS и TrueHD** — для браузеров и WebView.
- **Чересстрочное видео** — для браузеров (`bwdif` / `deinterlace_vaapi`). Для telecine с DVD — IVTC (`fieldmatch,decimate`).
- **Ограничение битрейта** — при просмотре вне дома.
- **Вжигание субтитров** — только iPhone в полноэкранном режиме или по явному переключателю.

### 5.4 Политика HDR и DV

| Источник | DV-клиент | HDR-клиент без DV | SDR-клиент |
|---|---|---|---|
| HDR10 / HLG / HDR10+ | copy | copy | Chrome/Edge ПК, Safari, Android 13+ — copy; остальным — серверный tone mapping |
| DV P8.x | copy (`dvh1` + `-strict unofficial`) | copy как `hvc1` | как HDR10 |
| DV P7 | Shield copy или офлайн `dovi_tool -m 2` → P8.1 | `-bsf:v dovi_rpu=strip=1` (FFmpeg 9.0: `dovi_split`) | strip + tone mapping |
| DV P5 | copy | libplacebo с DV-reshaping | то же |

Варианты tone mapping:
- **libplacebo через Vulkan** — лучшее качество;
- **`tonemap_vaapi`** — быстрый, только Intel;
- **`tonemap_opencl`** — нужен OpenCL ICD, которого в образе нет.

### 5.5 Политика звука

- **Копировать, если клиент умеет:** AC-3/E-AC-3 для Edge и Safari, passthrough на ТВ.
- **Иначе:**
  - Opus — Chromium и Firefox;
  - AAC — Safari;
  - E-AC-3 640k 5.1 — ТВ и Edge;
  - 5.1 при `maxChannelCount ≥ 6`;
  - FLAC — для lossless в локальной сети.
- **DTS-HD** → `-bsf:a dca_core`.
- **Даунмикс** — матрицей (`-ac 2` теряет LFE).
- **Громкость:** LUFS при сканировании + усиление на клиенте.

### 5.6 Сборка ffmpeg

- **Сейчас:** BtbN 8.1.3 gpl. Используются только `vaapi`/`cuda` + `h264_vaapi`/`h264_nvenc`/`libx264`, HEVC-кодирования нет. Наличие `libplacebo`/`zscale` в сборке не проверено — нужен `ffmpeg -filters` в образе.
- **jellyfin-ffmpeg 8.1.3-1** даёт:
  - DV/HDR tone mapping на AMD;
  - `tonemapx`;
  - `remove_dovi` / `remove_hdr10plus`;
  - DOVI в hlsenc;
  - аппаратное вжигание ASS.

  Решение о переходе — на этапе tone mapping.
- **Модель GPU на сервере неизвестна** — нужен `vainfo`. От неё зависят HEVC 10-бит-кодирование и путь tone mapping.

## 6. Целевая архитектура

### 6.1 Отчёт клиента (ClientCaps, JSON)

**Видео — по каждому кодеку:** `hw`, профили, битность, chroma, уровень, максимум `W×H@fps`, теги (`hvc1`/`dvh1`).

**DV:** профили и compat id.

**Экран:** HDR-типы, умеет ли ОС приводить HDR к SDR.

**Звук:**
- decode отдельно от passthrough;
- максимум каналов;
- есть ли FFmpeg-расширение.

**Субтитры:** text (srt/vtt/ass-basic/ass-libass) и image (pgs/vobsub/dvb).

**Контейнеры:** нужны ли Cues, `noSeek`.

**Сеть:** лимит, лимитное ли подключение.

**Как собирать:**
- **веб** — `MediaCapabilities.decodingInfo` (`smooth` как ограничение по разрешению), запасной `isTypeSupported`, `matchMedia('(dynamic-range: high)')`, `AudioContext.destination.maxChannelCount`;
- **Android** — логикой Media3: `MediaCodecUtil.getDecoderInfos` + `isFormatSupported(Format)`, `isHardwareAccelerated()`, `Display` HDR, `AudioCapabilities`.

**Сервер** исправляет известные баги устройств через список подмен и помечает возможность ложной при ошибке декодера.

### 6.2 Данные о файле при сканировании (MediaFacts, в БД)

- Все потоки: аудио с codec/ch/lang/default/forced/title; обложка исключена.
- DV-профиль, HDR10+.
- `field_order` и `idet`.
- Индекс ключевых кадров, есть ли Cues, zlib-сжатие дорожек MKV.
- LUFS по аудиодорожкам.
- Субтитры: формат, text/image, «сложность» ASS, шрифты из вложений, кодировка внешних текстовых файлов.
- Внешние дорожки: результат ETS + ffprobe (codec/channels/duration/start_time), `DELAY` из имени. Кеш по mtime каталога.

### 6.3 План воспроизведения (PlaybackPlan) — по каждому треку

- **Транспорт:** `File` | `HlsFmp4` | `HlsTs` | `Progressive` (только DLNA).
- **Видео:** `Copy` | `Copy+bsf` | `Transcode{codec, hw, filters}`.
- **Аудио (рендишны):** `Copy` | `CoreExtract` | `Transcode{codec, layout, bitrate, downmix}`.
- **Субтитры:** `Embedded` | `External(vtt|ass+fonts|sup)` | `Burn`.
- **`reasons[]`** показываются в HUD.

Кандидаты перебираются по цене, при ошибке — следующий план; неудача запоминается для пары «устройство + кодек».

### 6.4 Транспорт и живое переключение

**Direct Play исходного файла** везде, где клиент умеет. На ТВ Media3 сама перематывает MKV по Cues и переключает встроенные дорожки и субтитры **без перезапуска**.

**HLS fMP4 copy по индексу ключевых кадров** вместо прогрессивного `/api/video`:
- флаги Jellyfin: `-copyts -avoid_negative_ts disabled -start_at_zero`, `-hls_segment_options movflags=+frag_discont+skip_sidx`, `-tag:v hvc1`, +0,5 с к `-ss`;
- ffmpeg перезапускается вне окна сегментов.

**Аудио как отдельные рендишны** (`EXT-X-MEDIA TYPE=AUDIO`, по одному плейлисту на дорожку и на внешнюю озвучку, генерируются лениво). Смена дорожки — `hls.audioTrack = N` **без перезапуска видео**. Это убирает B3 и B10 для аудио.

**Качество (решено 21.10):**
- по умолчанию всегда **оригинал**: исходный файл или поток как есть (Direct Play, remux или copy), без перекодирования видео; «Auto» и ABR не делаем;
- если клиент оригинал не декодирует (например, Hi10P в Safari), неизбежный транскод идёт в исходном разрешении, без понижения, а HUD честно показывает «перекодировано, причина»;
- понижение — только руками в меню; каждая ступень — отдельный транскод по запросу.

**Субтитры всегда отдельно от видео:** VTT, ASS+шрифты, `.sup`. На ТВ — через `SubtitleConfiguration`/`MergingMediaSource` для внешних.

**Сессии:** ключ (userId, deviceId, path). Не трогать активные сессии других. Хвостовые сегменты меньше 0,5 с не объявлять.

### 6.5 Состояние плеера и память

- **Единое состояние, которое переживает любой перезапуск:** позиция, play/pause, mute, громкость, скорость, aspect/zoom, выбранные аудио и субтитры (включая внешние), сдвиги, метаданные сессии (B3).
- **Память по сериалу или фильму, на сервере для профиля:**
  - аудио: язык, «озвучка X», внешняя по имени папки;
  - субтитры: язык или выкл, forced, сдвиг;
  - aspect/zoom;
  - смещение синхронизации для конкретной озвучки.
- **Порядок выбора по умолчанию:** память тайтла → настройки профиля (язык аудио/субтитров, режим субтитров Default/Always/OnlyForced/None) → флаги default/forced → первая дорожка. Одинаково на вебе и ТВ.
  - Сервер может отдавать `defaultAudio`/`defaultSub` в ответе `start`, чтобы не было двойного старта (B11).

**Решение (21.10): память хранится на сервере, отдельно для каждого профиля.**

- **Таблица** `TrackPreferences` (userId, mediaItemId, опционально `season`):
  - аудио: язык + название или «отпечаток» дорожки (codec / каналы / title), либо внешняя озвучка по имени папки или суффиксу (`Russian Dub`, `.ukr`);
  - субтитры: язык + тип (полные / forced / signs) или «выкл», внешний файл по суффиксу;
  - сдвиг субтитров, смещение синхронизации для этой озвучки, aspect/zoom.
- **Запоминается по смыслу, а не по индексу.** У разных серий индексы дорожек и имена файлов разные, поэтому на следующей серии сервер ищет дорожку с тем же языком и названием или озвучку из той же папки (Tier 1). Не нашёл — откат на настройки профиля.
- **Запись:** клиент шлёт выбор при смене (`PUT /api/me/track-prefs/{mediaItemId}`), с дебаунсом.
- **Чтение:** сервер применяет память при старте и отдаёт итог в ответе `start` (`defaultAudio`, `defaultSub`, `externalAudio`, `subtitleOffset`, `aspect`). Так веб, телефон и ТВ ведут себя одинаково, а лишнего второго старта нет.
- **Для фильмов** ключ — сам тайтл, для сериалов — сериал (по умолчанию на весь сериал; отдельно по сезону, если у сезонов разные озвучки).

## Приложение A. Тестовые файлы

Файлы генерируются обычным ffmpeg. У каждой дорожки свой тон, по нему видно, что реально играет:
- rus — 440 Гц;
- eng — 880 Гц;
- jpn — 330 Гц;
- ukr (внешняя) — 660 Гц;
- `Russian Dub` — 550 Гц.

```bash
# 180 s MKV: counter + 3 audio + 2 SRT + styled ASS
ffmpeg -f lavfi -i testsrc=size=1920x800:rate=24:duration=180 \
  -f lavfi -i sine=frequency=440:duration=180 -f lavfi -i sine=frequency=880:duration=180 \
  -f lavfi -i sine=frequency=330:duration=180 -i rus.srt -i eng.srt -i styled.ass \
  -map 0:v -map 1:a -map 2:a -map 3:a -map 4 -map 5 -map 6 \
  -c:v libx264 -preset veryfast -g 96 -pix_fmt yuv420p \
  -c:a:0 ac3 -ac:a:0 6 -c:a:1 aac -c:a:2 libopus -c:s:0 srt -c:s:1 srt -c:s:2 ass \
  -metadata:s:a:0 language=rus -metadata:s:a:1 language=eng -metadata:s:a:2 language=jpn \
  -metadata:s:s:0 language=rus -metadata:s:s:1 language=eng -metadata:s:s:2 language=eng \
  "Show.S01E02.1080p.mkv"

# External dub next to the video (Tier 0) and in a dub folder (Tier 1)
ffmpeg -f lavfi -i sine=frequency=660:duration=180 -c:a libopus "Show.S01E02.1080p.ukr.mka"
ffmpeg -f lavfi -i sine=frequency=550:duration=180 -c:a aac "../Russian Dub/02.mka"

# Anamorphic 1440x1080 SAR 4:3 (DAR 16:9)
ffmpeg -f lavfi -i testsrc=size=1440x1080:rate=25:duration=20 -vf setsar=4/3 -c:v libx264 "Show.S01E04.1080p.mkv"
```

- Внешний SRT в **cp1251** сохранять с `encoding='cp1251'`.
- В ASS задавать стиль с `Alignment=8` (сверху) и строку с `{\pos(300,500)\frz15}`. Если стили потеряны, это сразу видно.

Определение частоты тона (Python, без зависимостей):

```python
import array, subprocess, sys
pcm = array.array('h', subprocess.run(['ffmpeg', '-v', 'error', '-i', sys.argv[1], '-map', '0:a:0', '-ac', '1',
      '-ar', '16000', '-t', '3', '-f', 's16le', '-'], capture_output=True).stdout)
zc = sum(1 for i in range(1, len(pcm)) if (pcm[i-1] < 0) != (pcm[i] < 0))
print(f'~{zc / 2 / (len(pcm) / 16000):.0f} Hz')
```
