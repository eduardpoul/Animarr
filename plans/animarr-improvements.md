# Animarr — План исправлений и улучшений

> Этот документ описывает проблемы, которые необходимо исправить, и возможности для улучшения проекта. Код не изменяется — только план действий.

---

## 1. Критические исправления (Fix)

### 1.1 Зафиксировать версии NuGet-пакетов
**Файл:** [`Animarr.Web.csproj`](src/Animarr.Web/Animarr.Web.csproj:11-15)

| Текущее значение | Проблема |
|------------------|----------|
| `Version="*"`    | Wildcard-версии приводят к непредсказуемым обновлениям и невозможности воспроизводимой сборки |

**Действия:**
- [ ] Определить актуальные версии всех пакетов через `dotnet list package`
- [ ] Заменить `*` на конкретные версии (например, `Version="9.0.0"`)
- [ ] Добавить комментарий с датой проверки версий

---

### 1.2 Устранить дублирование логики паттернов в RenameService
**Файл:** [`RenameService.cs`](src/Animarr.Web/Services/RenameService.cs)

| Метод | Строки |
|-------|--------|
| `ScanFolderAsync()` | 29–53 |
| `ProcessSingleFileAsync()` | 163–187 |

**Проблема:** Код объединения глобальных и папочных паттернов, фильтрации по типу папки и сбора ignore-правил полностью дублируется.

**Действия:**
- [ ] Выделить метод `BuildEffectivePatternsAsync(Guid folderId, CancellationToken ct)` в отдельный приватный метод или сервис
- [ ] Выделить метод `BuildEffectiveIgnoreRulesAsync(Guid folderId, CancellationToken ct)`
- [ ] Заменить дублирующийся код вызова этих методов

---

### 1.3 Добавить обработку конкурентных конфликтов EF Core
**Файл:** [`TorrentEngineService.cs`](src/Animarr.Web/Services/TorrentEngineService.cs)

| Метод | Строка |
|-------|--------|
| `OnStateChangedAsync()` | 270–273 |
| `OnMetadataReceivedAsync()` | 303–306 |

**Проблема:** `DbUpdateConcurrencyException` перехватывается и игнорируется без повторной попытки. Это может скрывать потерю данных.

**Действия:**
- [ ] Реализовать retry-логику с использованием `Microsoft.EntityFrameworkCore.Storage` для определения deadlock-ошибок
- [ ] Добавить логирование с уровнем `Warning` при каждом конфликте
- [ ] Рассмотреть использование оптимистичной блокировки (`ConcurrencyToken`) для `TorrentRecord`

## 2. Улучшения архитектуры

### 2.1 Рассмотреть переход на Blazor Hybrid или добавление WASM
**Файл:** [`Program.cs`](src/Animarr.Web/Program.cs:40-41)

**Текущее состояние:** Только `InteractiveServerComponents` (Blazor Server).

**Проблемы:**
- Потеря сессии при разрыве соединения
- Высокая нагрузка на сервер из-за полного DOM diffing
- Нет офлайн-работоспособности

**Действия:**
- [ ] Оценить возможность добавления `InteractiveWebAssembly` режима (hybrid rendering)
- [ ] Настроить SignalR reconnection с кастомной логикой восстановления состояния
- [ ] Рассмотреть добавление `blazor-reconnect` библиотеки для улучшения UX при переподключении

---

### 2.2 Миграция на более масштабируемую БД (опционально)
**Файл:** [`Program.cs`](src/Animarr.Web/Program.cs:15-25), [`Dockerfile`](Dockerfile:34)

**Текущее состояние:** SQLite — хороший выбор для single-instance, но имеет ограничения на конкурентный write-access.

**Действия:**
- [ ] Определить пороговое количество одновременных пользователей/торрентов, при котором SQLite становится узким местом
- [ ] Подготовить абстракцию над DbContext для возможной замены на PostgreSQL/MySQL
- [ ] Если миграция нужна: добавить EF Core провайдер для целевой БД, обновить Docker Compose с сервисом PostgreSQL

---

### 2.3 Добавить REST API для внешних интеграций
**Файл:** [`Program.cs`](src/Animarr.Web/Program.cs)

**Текущее состояние:** Только Blazor UI — нет API для Sonarr/Radarr/Telegram-ботов и т.д.

**Действия:**
- [ ] Добавить Minimal API endpoints:
  - `POST /api/torrents/magnet` — добавление торрента по magnet-link
  - `GET /api/torrents` — список всех торрентов
  - `GET /api/folders` — список папок
  - `POST /api/folders/{id}/scan` — сканирование папки
- [ ] Добавить API key аутентификацию (middleware или bearer token)
- [ ] Документировать endpoints в README

## 3. Улучшения надёжности

### 3.1 Валидация путей при добавлении FolderWatcher
**Файл:** Сервис или компонент для управления папками

**Проблема:** Нет проверки пути при создании/редактировании `FolderWatcher`.

**Действия:**
- [ ] Добавить валидацию: путь существует, доступен для чтения/записи
- [ ] Показать пользователю понятное сообщение об ошибке вместо исключения
- [ ] Рассмотреть кнопку "Проверить соединение" для сетевых путей

---

### 3.2 Логирование с ротацией файлов
**Файл:** [`Program.cs`](src/Animarr.Web/Program.cs)

**Проблема:** Логи по умолчанию выводятся только в консоль — неудобно для Docker и production.

**Действия:**
- [ ] Добавить Serilog или встроенный файловый провайдер логирования
- [ ] Настроить ротацию: по размеру (10 MB) и/или по времени (ежедневно)
- [ ] Хранить логи не более 30 дней
- [ ] Добавить уровни логирования для разных компонентов (Torrent, Rename, Watcher)

---

### 3.3 Graceful shutdown торрент-движка
**Файл:** [`TorrentEngineService.cs`](src/Animarr.Web/Services/TorrentEngineService.cs:163-174)

**Текущее состояние:** `ShutdownAsync()` вызывается в `finally`, но нет регистрации `IHostApplicationLifetime` для перехвата сигналов.

**Действия:**
- [ ] Зарегистрировать обработчик `ApplicationStopping` для graceful shutdown
- [ ] Остановить все торренты перед закрытием (pause, не remove)
- [ ] Сохранить состояние всех активных менеджеров в БД
- [ ] Добавить timeout (например, 30 секунд) — принудительно завершить если не успело
